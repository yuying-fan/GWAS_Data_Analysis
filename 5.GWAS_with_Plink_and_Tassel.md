# 5. GWAS with Plink and Tassel 

We will be using two software packages for association analysis: (1) Plink 1.90 and (2) TASSEL 5.0

First, make sure you are in the ```bamfiles``` folder

### Plink 1.90

We will be running association analysis using Plink 1.90. We have already downloaded Plink in the previous section to our ```bamfiles``` directory. Association analysis in Plink will be done using a linear regression with covariates.

We will be using principal component analysis (PCA) as a covariate in our GWAS. We will need to determine the number of principal components (PC) to use as covariates in our association analysis regression to help correct for population stratification in our sample set. This will be done by constructing a scree plot, ploting the number of PC on the x-axis and eigenvalues on the y-axis.

In Plink, we will extract the top 20 principal components. This is an arbitrary number (could go higher or lower) as we are going to use the scree plot to determine how many to use as covariates in our association analysis. To extract the top 20 PCs, input in the line below:
```
plink --bfile pihat_removed_3 --pca 20 header tabs --out PCA20
```
- ```--bfile``` to denote our inputing file, ```pihat_removed_3```, is a binary file set (```.bed``` + ```.bim``` + ```.fam```)
- ```--pca``` will extract the top "x" principal components, which we have set to as 20. The following ```header``` modifier adds a header line to the resulting .eigenvec file. The ```tabs``` modifier makes the .eigenvec file tab instead of space delimited.
- ```--out``` denotes the output file name, ```PCA20```

The results will be saved to two files ```PCA20.eigenval``` and ```PCA20.eigenvec```, which contain the eigenvalues and eigenvectors, respectively. 

You can look at the eigenvalues using ```cat PCA20.eigenval```, which will print a one-column list of the eigenvalues. You can then easily just copy and paste this printed list into an excel sheet and construct a line plot. I have inserted below the scree plot that is made:

![Scree Plot Plink](https://github.com/fany8/GWAS_BIO722/blob/main/Images/Screeplot_Plink.png)

From this plot, you can see there is an "elbow" in the graph. The bend of this elbow will be the cutting-off point in terms of the number of PCs to use for the following association analysis. From our scree plot, the "elbow" in our plot occurs at around 10 PCs before it starts to level off. Thus for our association analyses, we will be using 10 PCs as covariates.

We now have the genotype file, phenotype file and our PC covariates ready. We will now use these three files to do association analysis in Plink with the top 10 PC as covariates:
```
plink --bfile pihat_removed_3 --pheno AMBpheplink.txt --covar PCA20.eigenvec --covar-number 1-10 --linear hide-covar --allow-no-sex --out amb_plink_output
```
- ```--pheno``` is used to denote the phenotype file, ```AMBpheplink.txt```
- ```--covar``` denotes the file to load covariates from. ```--covar-number``` is used to specify the subset of covariates to load, by column number
- ```--linear``` performs a linear regression
- ```hide-covar``` removes covariate-specific lines from the generated main report. Otherwise, multiple lines will be outputed in for each covar (e.g. PC1, PC2, etc.)
- ```--allow-no-sex``` is required to retain phenotype values for missing-sex samples (in our case, without it, it would removal phenotype values for all our samples)

This will create three output files: ```amb_plink_output.log```, ```amb_plink_output.nosex```, and ```amb_plink_output.assoc.linear```.
- ```amb_plink_output.log``` is just the log file
- ```amb_plink_output.nosex``` lists the FID and IID of individuals with no sex, which would be all our strains
- ```amb_plink_output.assoc.linear``` will provide the association analysis results. This file will contain the p-values and is what we will use later on.

### Tassel 5.0

We will be doing GWAS also using [Tassel 5.0](https://www.maizegenetics.net/tassel). Still being in our ```bamfiles``` folder, we will download Tassel 5.0 by using:
```
git clone https://bitbucket.org/tasseladmin/tassel-5-standalone.git
```

This will create a folder named ```tassel-5-standalone``` in our ```bamfiles``` folder. The ```tassel-5-standalone``` folder contains the Tassel pipeline command line interface called ```run_pipeline.pl*```

Our genotype files are currently in Plink binary format (```pihat_removed_3.bed```, ```pihat_removed_3.bim``` and ```pihat_removed_3.fam```). We will need to convert this back into vcf format to run association analysis in Tassel. This can be done using Plink's ```--recode vcf```:
```
plink --bfile pihat_removed_3 --recode vcf-iid --out pihat_removed_3_tassel
```
- ```--recode vcf-iid``` will generate a vcf file, while removing the family IDs in the process. (If -iid is not included, the strain names in your genotype vcf file will go from DRR022916 to DRR022916_DRR022916)

Now we will work on the phenotype file for our Tassel GWAS as the required format for the phenotype file is slightly different than Plink's. We will create a new text file called ```AMBphetassel.txt``` in our ```bamfiles``` folder:

After saving the contents of ```AMBphetassel.txt```, we will now work on the association analysis. For GWAS, the general linear model (GLM) with a PCA model is expected to reduce false positives, therefore, we will also include PCA in our Tassel analysis.

We will run PCA in Tassel with 10 PC by inputting in the line below (_still being inside ```bamfiles```_):
```
./tassel-5-standalone/run_pipeline.pl -importGuess pihat_removed_3_tassel.vcf -PrincipalComponentsPlugin -covariance true -ncomponents 10 -endPlugin -export PCA10tassel
```
- ```-importGuess``` is used to denote the input genotype file, ```pihat_removed_3_tassel.vcf```. _```-importGuess <filename>``` uses Tassel's Guess function to load in the input file (you do not need to specify the file format (e.g. vcf, fasta) as Tassel will determine this by itself)_
- ```-PrincipalComponentsPlugin``` is used to perform the PCA
- ```-ncomponents``` is used to set number of PCs to 10
- ```-export``` denotes the name of the output file, which is ```PCA10tassel```

After PCA has finished running, three resulting files will be obtained: ```PCA10tassel1.txt```, ```PCA10tassel2.txt```, and ```PCA10tassel3.txt```. These files contain the principal components, the eigenvalues, and the eigenvectors, respectively. We will be using these three files when conducting our GLM analysis.

Now that we have all the input files needed for Tassel, we can run the GWAS via GLM (PCA) by inputting in the command below:
```
./tassel-5-standalone/run_pipeline.pl -fork1 -importGuess pihat_removed_3_tassel.vcf -fork2 -importGuess AMBphetassel.txt -fork3 -importGuess PCA10tassel1.txt -fork4 -importGuess PCA10tassel2.txt -fork5 -importGuess PCA10tassel3.txt  -combine6 -input1 -input2 -input3 -input4 -input5 -intersect -FixedEffectLMPlugin -endPlugin -export amb_tassel_output
```
- In TASSEL's command line, the pipeline can consist of multiple forks (i.e. sub-pipelines) which are denoted with ```-fork```. Each fork will have a name (e.g. -fork1, -fork2, -fork3). For better understanding of this fork process, a visualization can be found in page 13 of this [pdf](https://bytebucket.org/tasseladmin/tassel-5-source/wiki/docs/Tassel_Pipeline_Tutorial20160330.pdf?rev=5fd60a7601c229896edabbf8e8869b6ef522e464)
- The first fork, ```-fork1```, is used to import in our genotype vcf file, ```pihat_removed_3_tassel.vcf```
- The second fork, ```-fork2```, is used to import in our phenotype text file, ```AMBphetassel.txt```
- The third, fourth and fifth fork (```-fork2```, ```-fork3```, ```-fork4```) is used to import in our PC, eigenvalues and eigenvector files we created: ```PCA10tassel1.txt```, ```PCA10tassel2.txt```, and ```PCA10tassel3.txt```
- ```-combine6``` is then used to combine these 5 input files (```-input1 -input2 -input3 -input4 -input5```) into a single thread. ```-intersect``` follows after the ```-combine``` to join the input datasets based on taxa
- ```-FixedEffectLMPlugin``` is used to conduct the GLM association analysis
- ```-export``` denotes the name of the output file. We will be naming it ```amb_tassel_output```
 
This command will produce two files: ```amb_tassel_output1.txt``` and ```amb_tassel_output2.txt```. We will be using the first text file, ```amb_tassel_output1.txt``` for our next Visualization Section as it contains the p-values.

### Preparing the two output files for visualization 

You now have the two files containing p-values obtained from Plink and Tassel: ```amb_plink_output.assoc.linear``` and ```amb_tassel_output1.txt```. Using the information from these files we can construct Manhattan and QQ plots. But first we will need to reformat these files, keeping just the columns we need for our next section. 

We will start off with the Plink file ```amb_plink_output.assoc.linear```. Plink outputs this file with nine column headers (CHR, SNP, BP, A1, TEST, NMISS, BETA, STAT, P) and we will need the CHR, BP and P columns for our next visualization section. However, Plink outputs this file using multiple spaces as the delimiter and the number of spaces seperating each column is inconsistent (not the same number). Therefore, we will use the command below to create a new file called ```Plink_for_plot.txt``` with just the three columns we need:
```
cat amb_plink_output.assoc.linear | tr -s ' ' | cut -d ' ' -f 2,4,10 > Plink_for_plot.txt
```
- ```tr -s``` is used to convert these multiple consecutive spaces into a single space
- ```cut -d``` is then used to perform the cut operation with space as the delimiter. We want to pull out fields 2, 4, and 10 (The CHR column is considered as #2, not #1, because the plink file has spaces infront of this "first" column header)

We will do the same with the Tassel output ```amb_tassel_output1.txt```. The Tassel output is tab-delimited and contains 18 columns. The columns of interest for visualization are: Chr (column 3), Pos (column 4) and p (column 6). We will use a similar command to create a new file for our Tassel results called ```Tassel_for_plot.txt```:
```
cat amb_tassel_output1.txt | cut -f 3,4,6 > Tassel_for_plot.txt
```
- For ```cut```, we do not need to specify ```-d``` since tab is the default field delimiter character
