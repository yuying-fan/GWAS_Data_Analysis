# 3. Alignment and Variant Calling

### Aligning reads to reference genome

We will now be aligning our trimmed reads to the reference genome, Af293. To do this for all 32 strains, we will automate this process using a bash script.

Create a script called ```alignment.sh```:
```
nano alignment.sh
```

Inside of this script, input in the text below:
```
run=()

run=$(find /2/scratch/yuying/SEQAF -type d)

for id in $run

do

        idd=$(basename "$id")

        cd /2/scratch/yuying/SEQAF/${idd}

        f=$(find /2/scratch/yuying/SEQAF/${idd} -type f |grep _1.fastq|grep -v fastqc)

        R1=$(basename "$f")

        R2=${R1/_1.fastq/_2.fastq}

        p=${R1/_1.fastq/}

        echo $p

        bwa mem -t 16 /2/scratch/yuying/SEQAF/Af293.fa -R "@RG\tID:${p}\tLB:*\tPL:ILLUMINA\tPM:HISEQ\tSM:${p}" $R1 $R2 |samtools view -bS | samtools sort -o ${p}.sorted.bam

        java -jar /usr/local/picard-tools/picard.jar MarkDuplicates I=${p}.sorted.bam O=${p}.sorted.markdup.bam M=${p}.markdup_metrics.txt

        samtools index ${p}.sorted.markdup.bam

        cd ..

done
```
- This script will enter our strain directories, find the fastq files (not fastqc, ```grep -v```) and align the forward and reverse reads to the reference Af293 using [BWA-MEM](http://bio-bwa.sourceforge.net/bwa.shtml). 
- ```bwa mem -R``` is used to add read group headers to the alignment output.
- Converting from SAM to BAM is then done using [samtools](http://www.htslib.org/doc/samtools.html)', ```samtools view```.  ```-S``` is used to specify that the input is in SAM format and ```-b``` is used to mark that we want the output to be BAM.
- The script will then sort the bam files using ```samtools sort``` (```-o``` is just used to denote name of the output file to be saved) and mark duplicate reads using [MarkDuplicates](https://broadinstitute.github.io/picard/command-line-overview.html#MarkDuplicates) 
- Finally, it will index these bam files using ```samtools index```

After saving the changes, we can now run this script on our files with:
```
bash alignment.sh
```

### Variant calling

We will be variant calling using [FreeBayes](https://github.com/freebayes/freebayes). From [forums](https://www.biostars.org/p/342533/) and [GATK documentation](https://github.com/broadinstitute/gatk-docs/blob/master/blog-2012-to-2019/2016-06-01-Version_highlights_for_GATK_version_3.6.md?id=7712), indel realignment isn't done in the FreeBayes pipeline as FreeBayes performs a haplotype assembly step. Thus, we will be going directly into variant calling (_Note: we are still in the ```SEQAF``` directory_).

We will be making a new folder for all the bam files we just obtained called ```bamfiles```:
```
mkdir bamfiles
```

Then move all the ```.sorted.markdup.bam``` files and their corresponding index files (```.sorted.markdup.bam.bai```) to this new ```bamfiles``` folder:
```
mv ./*/*.sorted.markdup.bam* bamfiles/
```

After moving everything over, go into the ```bamfiles``` folder (```cd bamfiles```). Variant calling can now be done using FreeBayes. I will be doing this on a chromosome-by-chromosome basis, as doing all eight chromosomes at once will take a long time and doing it individually also allows calling SNPs in parallel. - Since this is being done chromosome-by-chromosome, we will specify the region using ```-r``` to give them the chromosome name (Af293 has the naming notation of NC_007194.1 to NC_007201.1 for its chromosome 1 to 8).
- We use ```-f``` to give it the reference file, ```Af293.fa```
- ```--ploidy``` is set to 1 as this is a haploid organism
- Freebayes can take in multiple bam files for joint calling, thus we will input in all our strain's bam files with ```*bam```.
- We will save the output file for each chromosome as ```allmergedx.vcf``` , where "x" is an interger denoting the chromosome number

After this is done, you have obtained eight allmerged vcf files (with all strains in one file). These files have been split based on chromosome so we will now combine all files to obtain one complete vcf file that has all eight chromosomes, which we will name ```fullmerged.vcf```. This will be done in two steps: (1) First is to grab the header off one of the allmerged vcf files (for this example we will use ```allmerged1.vcf``` but it does not matter which vcf you grab the header from) and then (2) concatenate all these allmerged vcf files without the header. 

The commands for these two steps are shown below:

**I) Grab the header from just one allmerged vcf file. In this example, we will use ```allmerged1.vcf```:**
```
grep '^#' allmerged1.vcf > fullmerged.vcf
```
**II) Concatenate all the vcf files together without headers:**
```
grep -h -v '^#' allmerged1.vcf allmerged2.vcf allmerged3.vcf allmerged4.vcf allmerged5.vcf allmerged6.vcf allmerged7.vcf allmerged8.vcf >> fullmerged.vcf
```
- ```-h``` will prevent the addition of filenames into your output when combining more than one file
- ```-v``` is used to exclude the headers (we already have the header from step 1 so we want to remove headers when combining now)

The result of this is a single vcf file for all 32 strains and all eight chromosomes, named ```fullmerged.vcf```, for us to use in the following sections.
