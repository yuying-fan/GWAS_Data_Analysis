# 2. Quality Control and Trimming

### Initial quality check of raw reads

An initial quality check of all the raw reads will be done using [FastQC](https://www.bioinformatics.babraham.ac.uk/projects/fastqc/). Since the fastq files are in multiple directories, a new script file called ```qualitycheck.sh``` will be made using the nano text editor:
```
nano qualitycheck.sh
```

Inside this file, input in:
```
run=()

run=$(find . -type d)

for id in $run

do
  	path=$(basename $id)
        cd /2/scratch/yuying/SEQAF/${path}

        fastqc *.fastq

        cd ..

done
```

Then run this script:
```
bash qualitycheck.sh
```

You can then compile all the quality reports using [MultiQC](https://multiqc.info/) by entering the command:
```
multiqc ./*
```
The resulting report will be saved in the SEQAF folder as ```multiqc_report.html```. This report can then be saved to your local computer using ```scp -r```. First, create a copy of it in your home directory with ```cp -r multiqc_report.html ~``` and then on your local machine, enter in this line, replacing the paths and account name with what would apply for you:
```
scp -r yuying@info.mcmaster.ca:/home/yuying/multiqc_report.html /Users/yuyingfan/Desktop/.
```

### Trimming reads

The samples that have failed any category of the quality report will be trimmed and then checked for quality again with FastQC. Looking at the MultiQC report, there are 26 strains that need to be trimmed.

We will first create a text file called ```failure.txt``` with nano editor.

```
nano failure.txt
```

After, we will create a bash script named ```trim.sh```
```
nano trim.sh
```

Inside, paste the script below and save the changes:
```
while read line; 

do

        cd $line

        mkdir clean_data

        id=$(find . -type f |grep _1.fastq | grep -v fastqc)

        R1=$(basename $id)

        R2=${R1/_1.fastq/_2.fastq}

        P=${id/_1.fastq/}

        java -jar /usr/local/trimmomatic/trimmomatic-0.36.jar PE -phred33 -threads 8 -trimlog ${p}_logfile $R1 $R2 clean_data/${P}_1.fastq clean_data/${P}_1.unpaired.fq clean_data/${P}_2.fastq clean_data/${P}_2.unpaired.fq ILLUMINACLIP:/usr/local/trimmomatic/adapters/NexteraPE-PE.fa:2:30:10 SLIDINGWINDOW:5:20 LEADING:5 TRAILING:5 MINLEN:50
	
	
        cd ..

done < failure.txt
```

Looking at the FastQC reports, adapter contamination is present in the form of Nextera Transposase adapters. 
This will create a new folder in the strain directory titled ```clean_data``` which will contain 4 output files after Trimmomatic is done. Two will have the extension ```_1.fastq``` and ```_2.fastq```, which are the paired output where both reads (forward and reverse) survived. The remaining two output files, which will have the extension ```_1.unpaired.fq``` and ```_2.unpaired.fq``` corresponding to the unpaired output where only one read survived (i.e. the other read did not). In this project, we will only be using the paired output.

You can now run this trimmomatic script using:
```
bash trim.sh 
```

Once this is complete, you can replace the old fastq files with the newly trimmed one by making another bash script, titled ```replace_trim.sh```
```
nano replace_trim.sh
```

Input inside the text seen below:
```
while read line;

do

        cd $line

        rm *logfile
        rm *fastq*

        mv clean_data/*fastq .

        rm -rf clean_data

     cd ..

done < failure.txt
```

You can then run this replacement script with
```
bash replace_trim.sh
```

### Quality check after trimming

Now you can check the quality again of just those trimmed fastq files. Do so by making another quality check script called ```qualitychecktrimmed.sh```
```
nano qualitychecktrimmed.sh 
```

Use the ```failure.txt``` file we previously made to specify which strains need to be FastQC-ed again by inputting inside of it:
```
while read line;

do

        cd $line

        fastqc *.fastq

        cd ..

done < failure.txt
```

Then run this script to FastQC just these 9 strains in the failure text:
```
bash qualitychecktrimmed.sh
```

Since MultiQC is quick, you can now compile **all** (i.e. 32 strains) quality reports using MultiQC. Since we already have the previous MultiQC directory and report html, we can specify the output directory name and report name using the ```-n``` flag. So this time, we will be entering the command:
```
multiqc ./* -n multiqc_report_new
```

Again, copy this report into your home directory to then copy over to your local machine. This is done using the same steps which I have listed below. Still in the SEQAF folder, do:
```cp -r multiqc_report_new.html ~```

On your local machine enter in this line, replacing the paths and account name with what would apply for you:
```
scp -r yuying@info.mcmaster.ca:/home/yuying/multiqc_report_new.html /Users/yuyingfan/Desktop/.
```
