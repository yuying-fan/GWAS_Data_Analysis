# 2. Quality Control and Trimming

### Initial quality check of raw reads

An initial quality check of all the raw reads will be done using [FastQC](https://www.bioinformatics.babraham.ac.uk/projects/fastqc/). Since the fastq files are in multiple directories, a new script file called ```qualitycheck.sh``` will be made using the nano text editor:
```
nano qualitycheck.sh
```

Inside this file, input in:
```
run=()

run=$(find . -type d)

for id in $run

do
  	path=$(basename $id)
        cd /2/scratch/yuying/SEQAF/${path}

        fastqc *.fastq

        cd ..

done
```
This script will look for directories in our current ```SEQAF``` directory, which are the strain directories contining the fastq files. For those strain directories, we will enter them and then run fastqc on files that have the ending ```.fastq```. This means in the end fastqc will be run on the forward and reverse ```.fastq``` files in our strain directories.

After saving the script, we will now run it:
```
bash qualitycheck.sh
```

After quality checking is complete, you can then compile all the generated quality reports using [MultiQC](https://multiqc.info/) by entering the command:
```
multiqc ./*
```

The resulting multiqc report will be saved into the current ```SEQAF``` folder as ```multiqc_report.html```. This report can then be saved to your local computer using ```scp -r```. First, create a copy of it into your home directory with ```cp -r multiqc_report.html ~``` and then on your local machine, enter in this line (replacing the paths and account name with what would apply for you):
```
scp -r yuying@info.mcmaster.ca:/home/yuying/multiqc_report.html /Users/yuyingfan/Desktop/.
```

### Trimming reads

The multiqc report will highlight strain in red that have failed a certain category. The strains that have failed any category of the quality report will be trimmed and then checked for quality again with FastQC. Looking at the MultiQC report, there are 26 strains that need to be trimmed.

We will first create a text file called ```failure.txt``` with nano editor:

nano failure.txt

After saving this text file, we will create a bash script named ```trim.sh```
```
nano trim.sh
```

Inside this file, paste the text below and save the changes:
```
while read line; 

do

        cd $line

        mkdir clean_data

        id=$(find . -type f |grep _1.fastq | grep -v fastqc)

        R1=$(basename $id)

        R2=${R1/_1.fastq/_2.fastq}

        P=${id/_1.fastq/}

        java -jar /usr/local/trimmomatic/trimmomatic-0.36.jar PE -threads 8 -trimlog ${p}_logfile $R1 $R2 clean_data/${P}_1.fastq clean_data/${P}_1.unpaired.fq clean_data/${P}_2.fastq clean_data/${P}_2.unpaired.fq ILLUMINACLIP:/usr/local/trimmomatic/adapters/NexteraPE-PE.fa:2:30:10 SLIDINGWINDOW:5:20 LEADING:5 TRAILING:5 MINLEN:50
	
	
        cd ..

done < failure.txt
```
This script will use the ```failure.txt``` accession numbers to enter strain directories that failed the quality check. In the strain folder, it will find the fastq files (not the fastqc files) and trim using trimmomatic. The script will also create a new directory inside the strain folder named ```clean_data```, which will contain 4 output files after Trimmomatic is done. Two will have the extension ```_1.fastq``` and ```_2.fastq```, which are the paired output, where both reads (forward and reverse) survived. The remaining two output files will have the extension ```_1.unpaired.fq``` and ```_2.unpaired.fq```, which corresponds to the unpaired output where only one read survived (i.e. the other read did not). In this project, we will only be using the paired output.
- Looking at the FastQC reports, adapter contamination is present in the form of Nextera Transposase adapters and thus we will use ```NexteraPE-PE.fa```


You can now run this trimming script using:
```
bash trim.sh 
```

Once this is complete, you can replace the old fastq files with the newly trimmed one by making another bash script, titled ```replace_trim.sh```
```
nano replace_trim.sh
```

Input inside the text seen below:
```
while read line;

do

        cd $line

        rm *logfile
        rm *fastq*

        mv clean_data/*fastq .

        rm -rf clean_data

     cd ..

done < failure.txt
```
This will just remove our old untrimmed files (we specify which folder are being replaced using just the strains listed in the ```failure.txt```) and replace them with the trimmed files found in the ```clean_data``` folder. After this is moved out, the ```clean_data``` folder is then deleted.

After saving the changes, we will run this replacement script with
```
bash replace_trim.sh
```

### Quality check after trimming

Now you can check the quality again of just those trimmed fastq files. Do so by making another quality check script called ```qualitychecktrimmed.sh```
```
nano qualitychecktrimmed.sh 
```

The script can be seen and copied from below:
```
while read line;

do

        cd $line

        fastqc *.fastq

        cd ..

done < failure.txt
```
We will use the ```failure.txt``` file we previously made to specify which strains need to be FastQC-ed again. This will specificy which strain folders to enter and fastqc the ```.fastq``` files from. 

Then run this script to FastQC just the strains in the failure text:
```
bash qualitychecktrimmed.sh
```

Since MultiQC is quick, you can just compile again **all** (i.e. 32 strains) quality reports using MultiQC. Since we already have the previous MultiQC directory and report html, we can specify the output directory name and report name using the ```-n``` flag. So this time, we will be entering the command:
```
multiqc ./* -n multiqc_report_new
```
- The ```-n``` will allow you to name the resulting report and output folder. Here, we have used the name ```multiqc_report_new```

Again, copy this report into your home directory to then copy over to your local machine. This is done using the same steps which I have listed the process again below:
```cp -r multiqc_report_new.html ~```

On your local machine enter in this line, replacing the paths and account name with what would apply for you:
```
scp -r yuying@info.mcmaster.ca:/home/yuying/multiqc_report_new.html /Users/yuyingfan/Desktop/.
```
