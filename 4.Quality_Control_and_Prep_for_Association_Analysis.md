# 4. Quality Control and Prep for Association Analysis

### Variant Filtering

For our first QC step, we will be filtering our SNPs with [vcftools](http://vcftools.sourceforge.net/) using thresholds for minimum allele frequency (MAF), call rate, quality score, and missingness. Our GWAS will be SNP-based and limited to biallelic markers, so we will also be using vcftools to remove indels and multiallelic sites. 

To do this quality control step, copy and run the line below on the ```fullmerged.vcf``` file _(Note: we are in the ```bamfiles``` folder)_:

```
/usr/local/bin/vcftools --vcf fullmerged.vcf --out filter_1 --remove-indels --max-alleles 2 --maf 0.05 --minQ 20 --max-missing 0.95 --recode --recode-INFO-all
```
- ```--vcf``` is used to denote the inputing vcf file, which would be our ```fullmerged.vcf``` file
- ```--out``` is used to name the resulting/outputing file as ```filter_1```
- ```--remove-indels``` excludes sites that contain an indel
- ```--max-alleles``` is set to 2 as we will be looking only at biallelic sites (i.e. removing multiallelic sites)
- ```--maf``` is set to 0.05. This will include only sites with a minor allele frequency (MAF) greater or equal to 0.05 (i.e. 5%)
- ```--minQ``` is set to 20 to only include sites with a Quality value equal or above this threshold
- ```--max-missing``` is set to 0.95 (i.e. 95%) to exclude genotypes called below 95% across all individuals
- ```--recode``` is used to generate a new vcf file after applying the filters. The output file will have the suffix ".recode.vcf". ```--recode-INFO-all``` is used along with it to keep all INFO values in the original input file.

### Linkage-Disequilibrium (LD) Pruning 

After obtaining the resulting ```filter_1.recode.vcf``` file, we will do LD pruning on this file.

LD pruning will be done using [Plink 1.90](https://www.cog-genomics.org/plink/), thus we will need to convert the vcf file into plink format. Our current vcf file (```filter_1.recode.vcf```) contains the chromosome name notation used in the reference genome Af293 (e.g. NC_007194.1 is chromosome 1) but there will be issues converting this into plink if our vcf file's "CHROM" column isn't numerical. Therefore, we will first convert these NC_00xxxx.x names into their numerical value using ```sed```

```
sed -i 's/NC_007194.1/1/g;s/NC_007195.1/2/g;s/NC_007196.1/3/g;s/NC_007197.1/4/g;s/NC_007198.1/5/g;s/NC_007199.1/6/g;s/NC_007200.1/7/g;s/NC_007201.1/8/g' filter_1.recode.vcf
```
- This command will replace NC_007194.1 with 1, NC_007195.1 with 2, NC_007196.1 with 3, and so on until the final chromosome 8.

Now that we have the CHROM column as numerical, we will convert our vcf file, ```filter_1.recode.vcf```, into plink format using vcftools by adding the ```--plink``` flag:

```
/usr/local/bin/vcftools --vcf filter_1.recode.vcf --plink --out filter_1plink
```

After this is done, you should now see two output files with the suffixes ".ped" and ".map", specifically ```filter_1plink.ped``` and ```filter_1plink.map```. These two files will be used in the LD pruning step.

We will now download and unzip Plink 1.90, by entering the two steps below (Note: You should still be in the ```bamfiles``` directory):

Download Plink 1.90:
```
wget https://s3.amazonaws.com/plink1-assets/plink_linux_x86_64_20210416.zip
```
Unzip this by entering:
```
unzip plink_linux_x86_64_20210416.zip 
```

You should now see a ```plink*``` in your ```bamfiles``` folder. Plink 1.90 can now be used to LD prune our files (```filter_1plink```). This is done by completeing the two steps below:

**1) Determine pruned out markers based on LD**

We will first determine a list of markers that will be pruned in and pruned out from our genotype file.
```
plink --file filter_1plink --indep 50 10 2 --out LDpruned
```
- ```--file``` to denote the inputing files, which would be ```filter_1plink```
- ```--indep``` to use variance inflation factors (VIF) to generate a pruned marker list. Here a window size of 50 SNPs is used. Actual pruning is done in the second step but the pruning works by Plink calculating LD between each pair of SNPs in that window, removing one of the pair of SNPS if VIF is greater than 2, and shifting the window 10 SNPs forward to then repeat these steps again. When pruning, PLINK keeps the SNP with the higher minor allele frequency and in situations of a tie, the first SNP is kept. 
- ```--out``` to denote the outputing/resulting file

The output of this step is two lists of SNPs: those that are pruned out (file with suffix ```.prune.out```; in this case ```LDpruned.prune.out```) and those that are not (file with suffix ```.prune.in```; in this case ```LDpruned.prune.in```). A seperate command using ```--extract``` is needed to actually perform the pruning, which will be done in the second step.

**2) Conduct the LD pruning**

After obtaining the pruned marker ID list called ```LDpruned.prune.in```, we will prune out markers by using the command below:
```
plink --file filter_1plink --extract LDpruned.prune.in --make-bed --out pruned_2
```
- ```--file``` denotes the inputing file, ```filter_1plink```
- ```--extract``` will accept a text file with a list of variant IDs and remove all unlisted variants from the inputted file (which is ```filter_1plink```)
- ```--make-bed``` will create a new PLINK binary fileset after applying the specified filters and/or operations (it will generate a .bed, .bim, and .fam file)
- ```--out``` denotes the outputing file name, ```pruned_2```

We now have finished LD pruning our genotype file and have created three files: ```pruned_2.bed```, ```pruned_2.bim``` and ```pruned_2.fam``` .

### Relatedness
After LD pruning is complete, we will now look at relatedness among our 32 strains.

We will analyse our genotype file for strains with cryptic relatedness and exclude individuals above the pihat threshold of 0.2 using Plink. For each pair of related individuals with a pihat > 0.2, we will remove the individual with the lowest call rate from the pair. 

To get started, we will enter the command below (_Note: still in the ```bamfiles``` folder_):
```
plink --bfile pruned_2 --genome --min 0.2 --out pihat_min0.2
```
- ```--bfile``` to denote our inputing file, ```pruned_2```, is a binary file set (```.bed``` + ```.bim``` + ```.fam```)
- ```--genome``` will calculate Identity by Descent (IBD) of all sample pairs. These calculations are not LD-aware and Plink suggests performing LD pruning in advance, which we have done in the previous step.
- ```--min``` is the minimum pihat value, which we have set at 0.2. When producing the list of strain pairs and their pihat values, it will remove lines with pihat values below that given cutoff before creating the report. 
- ```--out``` denotes the resulting file's name, ```pihat_min0.2```

We will now look at this list of strain pairs and their pihat values using the command below
```
cat pihat_min0.2.genome
```
You should then see this output:
![Relatedness](https://github.com/fany8/GWAS_BIO722/blob/main/Images/relatedness.png)

The report here shows that there are 3 groups of clonal relationships, having a pihat score of 1 between them:

Group 1: DRR022916 and DRR022924

Group 2: DRR022925, DRR022926 and DRR022927

Group 3: SRR8759700 and SRR8759706

This makes sense as some of the strains we are using were multiple samples obtained sequentially from the same patient (i.e. are clonal).

To decide which representative strain we should keep for each group, we will generate a summary statistic of missingness for each sample using ```--missing```:
```
plink --bfile pruned_2 --missing
```
- The command above will generate two files: ```plink.imiss``` and ```plink.lmiss```. 

These two files provides summary statistics that detail missingness by individual (```plink.imiss```) and by SNP (```plink.lmiss```). We are determining which strain to keep as the representative of the group based on missingness, therefore we will look at the ```plink.imiss``` file.

The ```plink.imiss``` file will contain 6 columns but the one we will focus on is the 6th column, ```F_MISS```. This column provides the proportion of missing SNPS for each individual. To look at the ```plink.imiss``` file and sort by the 6th column, we will input in the command below:
```
cat plink.imiss | sort -g -k 6
```
This is what you should see being printed:
![plink.imiss](https://github.com/fany8/GWAS_BIO722/blob/main/Images/plink.imiss.png)


Looking at the "F_MISS" column, we will be using this information to keep the strain with the highest call rate as the group representative. For each of the three clonal relationship groups, DRR022916, DRR022925, and SRR8759706 had the lowest "F_MISS" value and thus will be kept as the representative. Therefore, the remaining 4 strains will be removed from our genotype file and from further analysis.

To remove these 4 strains (DRR022924, DRR022926, DRR022927 and SRR8759700), we will create a text file containing their Plink IDs (Plink uses a Family ID and Individual ID). This is done to specify to Plink which strains should be removed.
```
nano removed_strains.txt
```

Inside this file, you need to provide the Family ID (FID) and Individual ID (IID) pair for each strain being removed, with one strain per line. The contents can be seen and copied from below:
```
DRR022924 DRR022924
DRR022926 DRR022926
DRR022927 DRR022927
SRR8759700 SRR8759700
```

After saving the changes, we will use the ```--remove``` command in Plink to remove these strains from our genotype file. We will call these new files ```pihat_removed_3```:
```
plink --bfile pruned_2 --remove removed_strains.txt --make-bed --out pihat_removed_3
```

After entering the command above, you should see that Plink loaded in 32 individuals, removed 4 individuals and now there are 28 individuals remaining in the genotype file. The output is three files: ```pihat_removed_3.bed```, ```pihat_removed_3.bim``` and ```pihat_removed_3.fam```

Prior to performing association analysis, we will do phenotype transformation. This will be done using RStudio and the package [bestNormalize](https://cran.r-project.org/web/packages/bestNormalize/vignettes/bestNormalize.html). This package will automatically find the optimal transformation for non-normally distributed phenotypes.

In RStudio, we will open up a new R Script. Set the working directory to what works for you (I used my Desktop: ```setwd("/Users/yuyingfan/Desktop/")```). Then copy the text below into your R Script and run:
```
# I first double-check that the file is there on my Desktop
file.exists("/Users/yuyingfan/Desktop/AMBphe.txt") 

# We will read the phenotype text file in and create a data frame from it. The header is set to TRUE as the first row should be treated as the column names ("Taxa  MIC"). The delimiter is also specified as tab and the character used for decimal points is "."
AMB <- read.table("/Users/yuyingfan/Desktop/YY_AZOLENEW/AMBphe.txt", header = TRUE, sep = "\t", dec = ".") 

# We will now open up the rcompanian package as we will be using "plotNormalHistogram" (information found here https://www.rdocumentation.org/packages/rcompanion/versions/2.4.0/topics/plotNormalHistogram)
library(rcompanion)

# Using the MIC values (second column), we will use plotNormalHistogram to quickly compare the distribution of our MIC data to a normal distribution.
plotNormalHistogram(AMB[,2])

# From the plot, we can see that the MIC data is not normally distributed thus we will use the bestNormalize package for it to determine the best transformation for our data.
library(bestNormalize)
BN_AMB <- bestNormalize(AMB[,2], allow_lambert_s = TRUE)
BN_AMB

# After running the steps above, you should see a message on how based off of the data, bestNormalize chose Standardized asinh(x) transformation. We will then let it perform the suggested transformation to our data with predict() and save this new information as "Transformed_AMB".
orderNormAMB <- predict(BN_AMB)
write.csv(orderNormAMB,"Transformed_AMB")
```
