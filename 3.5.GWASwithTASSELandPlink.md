After saving the phenotype file, we will start to work on the genotype file and all additional files TASSEL's association analysis requires. In TASSEL, we will be conducting our association analysis via a mixed linear model (MLM). In our analysis, a genetic marker based kinship matrix (obtained using Centered IBS) will be used in combination with population structure, obtained by principal component analysis (PCA). Therefore, to conduct MLM association analysis in TASSEL, we need 4 files: the genotype file, the phenotype file, a kinship matrix, and a population structure file.

First, we will obtain the population structure file. We will start off by doing a PCA using our genotype file ```pruned_2tassel.vcf```. We will first run this using 20 PCs. This file will help us deteremine how many PC we will actually include in our association analysis to explain for population structure.

```
./tassel-5-standalone/run_pipeline.pl -importGuess pruned_2tassel.vcf -PrincipalComponentsPlugin -covariance true -ncomponents 20 -endPlugin -export PCAtassel
```
- ```-importGuess``` is used for the input genotype file, ```pruned_2tassel.vcf```. _```-importGuess <filename>``` uses TASSEL's Guess function to load in the input file (you do not need to specify the file format (e.g. vcf, fasta) as TASSEL will determine this by itself)_
- ```-PrincipalComponentsPlugin``` is used to perform the PCA
- ```-ncomponents``` is set to 20 principal components (PC). This is an arbitrary number (could set it to 10, 15, etc. instead). We will be using the results to determine number of components to actually use in our analysis. 
- ```-export``` is used for the name of the output files

After PCA has finished running, three resulting files will be obtained named PCAtassel1.txt, PCAtassel2.txt, and PCAtassel3.txt. These files contain the principal components requested by user, the eigenvalues, and the eigenvectors, respectively.

A plot of the eigenvalues versus PCs will be used to help decide which PC's are most important to be used for the association analysis. This can be done by just copying the eigenvalues from ```PCAtassel2.txt``` into Excel and making a scatter plot with PC components on x-axis and eigenvalues on y-axis (this plot is called a scree plot). The scree plot obtained from TASSEL, with an x-axis up to 20 PCs, can be seen below:

![Image of Scree Plot from Tassel](https://github.com/fany8/GWAS_BIO722/blob/main/Images/Screeplot.png)

From this plot, you can see there is an "elbow" in the graph. The bend of this elbow will be the cutting-off point in terms of the number of PCs to use for the association analysis. From our TASSEL obtained PCA results, the "elbow" in our plot occurs at around 9 PCs before it begins to level off. Therefore, we will be using 9 PCs for our association analysis.

We will then run the PCA command again but this time with just 9 PCs. We will be save this as ```PCA9tassel```, which will later be used as the population structure file for our MLM analysis:
```
./tassel-5-standalone/run_pipeline.pl -importGuess pruned_2tassel.vcf -PrincipalComponentsPlugin -covariance true -ncomponents 9 -endPlugin -export PCA9tassel
```

We will now obtain the kinship matrix using our genotype file by running TASSEL's Kinship plugin
```
./tassel-5-standalone/run_pipeline.pl -importGuess pruned_2tassel.vcf -KinshipPlugin -method Centered_IBS -endPlugin -export kinship
```
- ```-importGuess``` is used for the input genotype file, ```pruned_2tassel.vcf```.
- ```-KinshipPlugin``` is the plugin used to generate a kinship matrix from a genotype file.
- ```-method``` is set to Centered_IBS, as to calculate the kinship matrix using Identity by state (IBS) method
- ```-export``` is used to denote the name of the output file

After running the above command, you should see a resulting kinship matrix file named ```kinship.txt```

After obtaining all the required files, we will now be running the association analysis via a MLM: 
```
./tassel-5-standalone/run_pipeline.pl -fork1 -importGuess pruned_2tassel.vcf -fork2 -importGuess AMBphetassel.txt -fork3 -importGuess PCA9tassel1.txt  -combine4 -input1 -input2 -input3 -intersect -fork5 -importGuess kinship.txt -combine6 -input5 -input4 -mlm -export amb_tassel_output
```
- The pipeline will be run using ```run_pipeline.pl```, which is found in the ```tassel-5-standalone``` folder
- In TASSEL's command line, the pipeline can consist of multiple forks (i.e. sub-pipelines) which are denoted with ```-fork```. Each fork will have a name (e.g. -fork1, -fork2, -fork3). For better understanding on this fork process, it has been visualized in page 11 on this [source](https://bytebucket.org/tasseladmin/tassel-5-source/wiki/docs/Tassel_Pipeline_Tutorial20160330.pdf?rev=5fd60a7601c229896edabbf8e8869b6ef522e464)
- The first fork, ```-fork1```, is used to import in our genotype vcf file, ```pruned_2.vcf```
- The second fork, ```-fork2```, is used to import in our phenotype text file, ```AMBpheTASSEL.txt```
- The third fork, ```-fork3```, is used to import in our population structure file, ```PCA9tassel3.txt```, which is the principal components file we obtained from our previous PCA step. 
- ```-combine4``` is then used to combine these 3 input files (```-input1 -input2 -input3```) into a single thread. ```-intersect``` follows after the "-combine" and joins input datasets based taxa
- The fifth fork, ```-fork5```, is used to import in our kinship matrix file, ```kinship.txt```
- ```-combine6``` is used to combine the kinship matrix and our previously joined file (containing genotype, phenotype and population structure)
- ```-mlm``` is used to conduct the MLM association analysis
- ```-export``` is used to name the output file. We will be naming it ```amb_tassel_output```
 
This will produce three files: ```amb_tassel_output1.txt```, ```amb_tassel_output2.txt```, and ```amb_tassel_output3.txt```. We will be using the second text file ```amb_tassel_output2.txt``` as it contained the p-values for our next Visualization Section. 

However, before moving onto that step, we will also be conducting association analysis with Plink.

### PLINK 1.90

We will next be running association analysis using PLINK 1.90. We already have downloaded PLINK 1.90 in our previous steps to our ```bamfiles``` directory. This will be done using a linear regression with covariates.

We will first analyse our genotype file for strains with cryptic relatedness. We will exclude all individuals above the pihat threshold of 0.2. For each pair of related individuals with a pihat > 0.2, we will remove the individual with the lowest call rate from the pair. 

```
plink --bfile pruned_2 --genome --min 0.2 --out pihat_min0.2
```

```

```

Looking at ```plink.imiss```, we will be only keep one sample from each group as the representative of the group. By looking at the "F_MISS" column, which column represents the proportion of missing SNPs in the individual, we will be using this information to keep the strain with the highest call rate.

For each group, DRR022916, DRR022925, and SRR8759706 had the lowest "F_MISS" value and thus will be kept as the individual group representative. Therefore, the remaining 7 strains will be removed from further analysis.
